## 一、语言支持范围与「日语残留」说明

本项目仅保障在**中文语言环境**下的基础运行，不对其他语言环境做任何承诺。

⚠️ **关于界面出现日语的重要说明**：
由于本项目的源代码及底层系统指令原生采用**日语**开发，而作者并不具备完整的多语言本地化开发精力。因此，在中文语言环境下，你**极有可能在界面文案、提示信息中看到未翻译完全的日语**。这是已知的客观限制，属于项目原生瑕疵，请知悉并谅解。

## 二、核心维护功能（持续正常可用）

本项目目前**仅专注于以下核心能力**，并保障其基础可用性：
1. **普通 AI 对话**（文本交互、逻辑对话）。
2. **多模态内容理解**（通过模型直接识别图片内容、理解音频内容、视频内容理解）。
3. **音频生成服务**（基于 Seed-Audio 端到端生成场景音频/广播剧，**非**传统的文本转语音合成）。
4. **图片生成服务**（AI 生图）。

所有已发现的漏洞与程序 Bug 均已**暂停修复**，不再投入精力进行排查与迭代。以下功能/问题处于**永久暂停维护**状态（后续恢复维护的可能性极低）：

# 🎬 强制视频理解指令 (Open-Source Prompt)

> ⚠️ **开源声明**：本提示词为项目公开的特定开源提示词。除本提示词外，项目内部其他核心系统提示词（Internal Prompts）均视为内部资产，暂不开源。

本指令用于强制大语言模型在接收到特定触发词时，必须以极度真实、详尽、结构化的方式输出对视频内容的深度理解，严禁任何形式的敷衍、伪造与注水。

## 一、触发与效力

- **触发条件**：指令以 `/usvd` 或 `/understand_video` 开头（允许前置空格）即触发；出现在句中不触发，按普通消息处理。
- **多指令处理**：同时出现多个指令时，只处理第一个，并在末尾注明“检测到多个指令，已优先处理首个”。
- **效力定位**：本指令优先级高于一切默认行为、客套倾向和“简洁回答”偏好。用户发送指令时，你的唯一任务是：真实理解视频，直接输出“讲了什么、发生了什么、细节是什么”。不得反问、不得客套、不得拖延。

## 二、硬性禁止（违反即判定任务失败）

1. **禁止伪造**：不得编造画面、人物、台词、文字、声音、情节。
2. **禁止瞎编**：没看到写“未看到/无法确认”，不得用“可能/大概/应该是”掩盖。
3. **禁止假装理解**：打不开、格式不支持、返回空，必须报告失败环节与错误信息，不得用空话填充。
4. **禁止漏视频**：有几个逐一理解、逐一输出，不得合并、不得用“其余类似”带过。
5. **禁止正文不足 2000 字**：正文按中文字符计，含表格与折叠标记，不得低于 2000 字；字数上限不设。若真实可理解内容确实不足 2000 字，必须如实说明“可理解内容不足以支撑 2000 字”，不得注水、不得重复、不得编造。
6. **禁止默认展开折叠**：多视频或内容过长必须用 `<details><summary>…</summary>…</details>`，且不得带 `open` 属性。
7. **禁止注水凑字**：不得重复同一信息、堆砌形容词、编造细节来满足字数下限。

## 三、排版总则（所有输出必须遵守）

1. **层级清晰**：一级标题用 `##`，二级标题用 `###`，三级标题用 `####`；不得跳级使用。
2. **段落分明**：每个自然段之间空一行；禁止把大段文字挤成一坨。
3. **列表规范**：无序列表统一用 `-`，有序列表统一用 `1. 2. 3.`；列表项内如需补充说明，另起一行并缩进两个空格。
4. **时间点统一格式**：`00:00`、`03:12`，不得写成“第3分12秒”等混用格式；时间点后用空格再接事件描述。
5. **表格规范**：表格前后各空一行；表头与分隔行必须完整；单元格内不换行，长内容用短句概括。
6. **引用与抄录**：画面文字、字幕原样抄录时用行内代码包裹，如 `示例文字`；整段台词用引用块 `> ` 包裹。
7. **强调克制**：加粗仅用于关键结论、失败状态、时间点标签；不得整段加粗。
8. **折叠块规范**：`<details>` 与 `<summary>` 各占一行，内部内容与标签之间空一行，`</details>` 单独占一行；不得带 `open` 属性。
9. **空行纪律**：标题前后各空一行；表格前后各空一行；折叠块前后各空一行；禁止连续三个以上空行。
10. **禁止装饰性符号**：不得用 ★★★、！！！ 等花哨分隔线或表情符号堆砌排版；分隔用 Markdown 水平线 `---`，且每节最多一条。
11. **失败与不确定标注**：失败状态用加粗 **理解失败：原因**；不确定内容在句末标注 `（不确定）`。

## 一、这是什么

**Dart · DeepSeek Harness**（下文简称 **ddsh**）是一个**自己托管、自己享用**的 AI 前端 + 后端一体项目。

它不是"又一个网页壳子"，而是把一整套后端能力塞进了一个 Dart 进程里：

- **一个进程就是一个服务**：`dart run bin/main.dart` 启动后，浏览器打开 `http://127.0.0.1:9999` 就是完整应用；没有 Node、没有数据库、没有 Docker。
- **两个模型家族**：DeepSeek 系（flash / v4-pro / reasoner 等）与火山方舟豆包系（seed-2.1-lite / pro / turbo、图像、视频、语音）。
- **数据全在本地**：会话、论坛、单词本、文件、备份，全部落在 `data/` 目录；密钥加密后落盘，不上传任何第三方服务器。
- **工具模式能动手**：通过 adb（uid=2000，等同 shell 权限）实现点击、滑动、输入、截图、OCR、开关应用——让模型真的能替你在手机上干活。

一句话：**它是给"想拥有自己一台 AI 服务器"的人准备的，而不是给"想注册一个账号"的人准备的。**

## 二、核心特性一览

### 🧠 对话与推理

- 多会话管理：新建、重命名、搜索（支持正则）、批量删除、会话内引用（`@` 提及其他会话）。
- 深度思考：DeepSeek reasoning 与豆包 thinking 双通道，思考链可折叠，不占正文。
- 联网搜索、翻译、图像生成、TTS 朗读、语音输入（STT）、实时语音通话。
- **模型路由**：可按任务把不同模型分流；自定义模型名可随时追加。

### 🌐 六语言界面

- `ja`（默认源语言）/ `zh` / `en` / `ko` / `ru` / `fr`，运行时热切换，无需刷新。
- 词典分片加载（`*-extra.js`），新增文案必须六语同步，杜绝"中文界面蹦出日语"。

### 📦 内容管理

- **文件管理**：64 MB 分片上传、断点续传式合并、单文件上限 5 GB、流式写盘防 OOM。
- **备份 / 还原**：一键打包 `data/` 为 tar.gz 下载，上传即可还原。
- **论坛**：本地发帖广场、详情页、批量清理。
- **单词本**：日语单词卡、假名、音调、词性、例句、配图、标签、等级筛选、间隔复习。
- **角色扮演（Cosplay）**：Tavern v2 风格角色卡，人格 / 场景 / 开场白 / 对话样例。
- **公告**：置顶优先级、生效时间窗、强制阅读。
- **峰谷提醒**：DeepSeek 错峰时段提示，帮你在便宜时段跑重活。

### 📱 设备操控（可选）

- `adb_up.sh` 拉起 adb 服务并校验 `uid=2000`。
- `auto.py` 安卓全自动操作引擎：点击、滑动、找控件、清弹窗、等稳定、中文输入、截图、OCR。
- 项目内置几十个 `fnTool` 工具定义，模型可自主调用。

### 🎨 工程细节

- 单文件可执行（`dart compile exe` → `app`），启动秒级。
- JIT 自动回退：AOT 不可用时自动 `dart run`。
- `st.py` 管理守护进程、日志、状态、Termux 服务注册。
- 全站暗/亮主题、移动端优先、`viewport-fit=cover` 适配刘海屏。

> 请从 **F-Droid** 或 **GitHub Releases** 安装。

1. 打开 F-Droid，搜索 `Termux`，安装。
2. 可选但强烈建议：同时安装 `Termux:Boot`（开机自启）与 `Termux:API`（通知、剪贴板、震动等）。


5. 允许 Termux 访问存储（备份、文件管理要用）：

弹出权限框时点「允许」。

6. **防杀设置（非常重要，安卓会偷偷杀后台）**：

## 七、六语言系统与语言纯净规则

### 7.1 支持的语言

| 代码 | 语言 | 说明 |
|---|---|---|
| `ja` | 日本語 | **源语言**，词典缺项时的兜底 |
| `zh` | 简体中文 | 全量覆盖 |
| `en` | English | 全量覆盖 |
| `ko` | 한국어 | 全量覆盖 |
| `ru` | Русский | 全量覆盖 |
| `fr` | Français | 全量覆盖 |

### 7.2 语言是怎么工作的

1. **源串是日语**。`index.html` 与各 JS 里写的都是日语原文。
2. **`i18n.js` 拦截并替换**：启动时读取 `html[lang]`，没有就用 `DEFAULT_LANG`（`ja`）。
3. **匹配顺序**：精确匹配 → 数字归一化（`3 件` ↔ `3 items`）→ 最长子串部分匹配 → `{0}` `{1}` 占位符插值。
4. **DOM 遍历翻译**：`TreeWalker` 扫文本节点与 `title`/`placeholder`/`aria-label` 等属性。
5. **跳过区**：用户生成内容（公告正文、论坛正文）、代码块、`pre` 不翻译——**AI 的回答永远原样保留**。
6. **热切换**：切换语言会重载词典并重扫 DOM，无需刷新页面。

### 7.3 语言纯净规则（本项目硬性要求）

> **中文界面下不得出现日语；其他语言界面下不得出现该语言之外的"母语残留"。**

具体含义：

- `zh` 界面出现任何日语原文 → **bug**。
- `en` 界面出现中文或日语 → **bug**。
- `ko` / `ru` / `fr` 界面出现中文品牌名（如「豆包」「墨迹」）→ **bug**，应转写为 `Doubao` / `Moji`。
- 日语界面**允许**出现日语（它本来就是源语言）。

### 7.4 怎么自检语言残留

在 `ddsh` 目录执行：

```bash
# 1) 词典条目数是否六语一致
for f in i18n/locales/{ja,zh,en,ko,ru,fr}.js; do
  printf "%-28s %s\n" "$f" "$(grep -c '|' "$f")"
done

# 2) 译文里是否混入中日文字符（应输出 0）
grep -nP '[\x{3040}-\x{30ff}\x{4e00}-\x{9fff}]' i18n/locales/en.js | head

# 3) 是否有空译文（形如 "键|" 结尾）
grep -nE '\|[[:space:]]*$' i18n/locales/*.js | head
```

三类问题的修复方式：

- **条目数不齐**：以 `en.js` 的键为准，补齐其余语言。
- **出现跨语言字符**：把品牌名统一转写为拉丁字母形式。
- **空译文**：补上实际文本，否则界面上该文案会直接消失。

### 7.5 新增一条文案的正确姿势

1. 在 HTML/JS 里写**日语源串**（不要写中文当源串）。
2. 在 `i18n/locales/` 下 **6 个语言** 各加一条 `日语源串|译文`。
3. 若文案带变量，用 `{0}` `{1}` 占位，不要拼接字符串。
4. 改完把 `index.html` 里对应 JS 的 `?v=` 版本号 +1，避免浏览器缓存旧词典。

## 八、聊天功能完全指南

### 8.1 会话管理

| 操作 | 路径 |
|---|---|
| 新建 | 顶部 ＋ |
| 重命名 | 点标题 |
| 搜索 | 侧边栏搜索框（可开正则） |

### 8.2 发送消息

- 直接输入回车即发送（可在设置里改为 Shift+Enter 换行）。

- 流式输出过程中点「停止」会中断并保留已生成内容。

### 10.4 视频理解（重点）

视频链路的两种模式：

| 模式 | 说明 | 适用 |
|---|---|---|
| 本地直传（默认） | multipart 上传到方舟 `/files`，再引用 | 绝大多数场景，**推荐** |
| TOS 引用 | 只发 `tos://桶/路径`，方舟自己去桶里读 | 你已把文件放进**自己有权限的桶** |

**关于 `TosResourceNotFound` (HTTP 404)：**

- 含义：方舟按你给的 `tos://...` 去读对象，**桶里没有这个文件**。
- 常见原因：桶名用了官方示例桶（如 `large-video-understand-000`，不归你账号）；文件只在手机本地、从未上传；路径拼错；桶未授权方舟读取。
- 处理：`useFilesApi` 默认为 `false`，即默认走**本地直传**，不会发出注定 404 的引用请求。TOS 引用只在 `useFilesApi=true` 且 `tosBucket` 非空时启用；此时必须确认桶属于你自己的账号，并已授权方舟读取。

**关于预处理显示「0 秒」：**

- 这是**显示 bug**，不是真的 0 秒。
- 原因：后端轮询预处理进度时只发 `stage: preprocess_wait`、不带 `waited` 字段，前端 `obj.waited || 0` 于是恒定显示 0。
- 现状：已修——首帧显式给出 `waited: 0` 作占位，其后每个 tick 通过 `onTick(status, waitedSec)` 回传真实秒数；前端拿到有效数字才渲染数字。

### 10.5 豆包配置在哪

`data/deepseek_chat/doubao_config.sts`（加密），以及视频相关 `doubao_video_ark.json`、`doubao_ark_files.sts`。

## 十一、Token 计费与价格显示

### 11.1 显示位置

每条 AI 回复**气泡下方**：

```
输入 8,420 · 命中 6,000 · 未命中 2,420 · 输出 640 · 合计 9,060   💰 ¥0.0079
```

长按或悬停金额，可看单价明细。

### 11.2 豆包 2.1-lite 价目（元 / 百万 tokens）

| 项目 | 单价 |
|---|---|
| 输入（未命中缓存） | 0.8 |
| 输入（缓存命中） | 0.16 |
| 输出 | 2.7 |
| 音频输入（未命中） | 12 |
| 音频输入（命中） | 2.4 |

- **无峰谷倍率**（`flat`），任何时段同价。
- 音频 token 单独按音频单价计，**不会**再按文本输入价重复计一次。
- 模型名带版本后缀（如 `doubao-seed-2-1-lite-260915`）也能正确匹配价目。

### 11.3 计算公式

```
金额 = 未命中输入/1e6 × 0.8
     + 命中输入/1e6   × 0.16
     + 输出/1e6       × 2.7
     + 音频未命中/1e6 × 12
     + 音频命中/1e6   × 2.4
```

**举例**：输入 1 万（其中命中 6 千、未命中 4 千）、输出 1000：

```
4000/1e6×0.8 + 6000/1e6×0.16 + 1000/1e6×2.7
= 0.0032 + 0.00096 + 0.0027
= ¥0.00686
```

### 11.4 数据会保存吗

会。usage 随消息一起写入 `.sts`，字段包括：

- `promptTokens`（输入总数）
- 缓存命中 / 未命中
- `completionTokens`（输出）
- `audioInputTokens`（音频输入）
- `model`（哪个模型算的）

所以：**刷新页面、重启后端、切换模型，历史消息的 token 都不会消失**，也不会被别的模型价目串算。

> ⚠️ 需要说清楚：**永久保存的是 token 原始计量**；金额是按"当前价目"实时算出来的。
> 因此当你调整单价（例如把命中价改成 0.16）后，**历史消息的金额会同步变低**——这是正确行为，不是数据丢失。

### 11.5 未定价模型

豆包 pro / turbo 等尚未在价目表里的模型，**只显示 token，不显示金额**。本项目不会编一个假价格糊弄你。

## 十五、ADB 自动化工具链

这一章是"让 AI 真的能操作手机"的部分。

### 15.1 原理

```
ddsh 后端
  └─ adb（127.0.0.1:5555，uid=2000 shell 权限）
       └─ auto.py / 底层 adb shell 命令
            └─ Android 系统：点击、滑动、输入、截图、启停应用
```

`uid=2000` 是 `shell` 用户，权限接近 Shizuku，但**不需要 root、不需要 Shizuku**。

### 15.2 打开无线调试（一次性设置）

1. 设置 → 关于手机 → 连点「版本号」7 次 → 开启开发者选项。
2. 设置 → 系统 → 开发者选项 → 打开 **USB 调试** 和 **无线调试**。
3. 无线调试 → 使用配对码配对（首次需要，配一次即可）。

### 15.3 拉起通道

```bash
cd ~/ddsh
bash adb_up.sh
```

脚本做三件事：

1. 用 `setsid` 起一个脱离终端的 adb server（不会随 shell 退出而死）。
2. `adb connect 127.0.0.1:5555`。
3. 用 `adb -s 127.0.0.1:5555 shell id` 校验是否拿到 `uid=2000`。

成功输出：

```
✅ 接続済み 127.0.0.1:5555  (uid=2000(shell))
```

失败会提示你去检查「无线调试」是否开启。

### 15.4 auto.py 能干什么

```bash
python3 auto.py -h
```

| 能力 | 说明 |
|---|---|
| 点击 / 长按 / 滑动 | 坐标或控件定位 |
| 找文字控件 | 按 `text` / `resource-id` 查找 |
| 弹窗清理 | 自动识别并关掉广告/权限弹窗 |
| 等待 | 等元素出现、等界面稳定 |
| 文本输入 | 中文 / emoji 全支持（自动切 ADB Keyboard，输完切回） |
| 剪贴板 | 复制、剪切、粘贴、读取、全选、清空 |
| 应用管理 | 启动、停止、卸载 |
| 截图 / OCR | 抓屏与文字识别 |
| 通知 | 发系统通知 |

设计特点：掉线自动重连、失败自动重试、超时保护。

### 15.5 输入法的正确姿势（硬性规范）

用 adb 输中文**不能**直接 `input text`，必须走 ADB Keyboard 广播。标准流程：

```bash
# 1. 查输入法列表
adb shell ime list -s

# 2. 切到 ADB Keyboard
adb shell ime enable com.android.adbkeyboard/.AdbIME
adb shell ime set com.android.adbkeyboard/.AdbIME

# 3. 校验
adb shell settings get secure default_input_method

# 4. 发文本（中文/emoji 必须 Base64）
adb shell am broadcast -a ADB_INPUT_B64 --es msg "<base64>"

# 5. 输完必须切回搜狗
adb shell ime set com.sohu.inputmethod.sogou/.SogouIME
adb shell settings get secure default_input_method
```

> 原则：**先切换 → 再输入 → 必校验 → 终恢复**。
> 用户手机的输入法状态是"圣地"，你走进去什么样，出来必须什么样。

### 15.6 常见失败

| 现象 | 原因 | 处理 |
|---|---|---|
| `adb connect` 成功但 `id` 不是 uid=2000 | 无线调试未授权 | 重新配对 |
| 命令全部超时 | adb server 被系统杀了 | 重跑 `adb_up.sh`；给 Termux 关电池优化 |
| 找到控件但点击无效 | 坐标被弹窗挡了 | 先 `auto_dismiss_dialogs` |
| 输入法切不回来 | 搜狗未安装 | 先装搜狗，或改脚本里的 IME 常量 |

## 十六、数据格式与安全模型

### 16.1 `.sts` 是什么

不是 JSON，而是**管道分隔的纯文本**。以会话为例，每行一条消息：

```
#M|id|role|content|createdAt|attachments|reasoning
```

转义规则（`escDs`）：

| 原始 | 转义后 |
|---|---|
| 换行 | `\n`（字面两字符） |
| `|` | `\p` |
| `\` | `\\` |

好处：单行存储、易 grep、易增量追加、坏一行不会毁整个文件。

### 16.2 加密

| 项目 | 实现 |
|---|---|
| 算法 | AES-256-GCM |
| 实现 | 纯 Dart（`aes_gcm.dart`），无第三方库 |
| 主密钥 | `DS_MASTER_KEY` 环境变量或 `ds_master.key`（32 字节） |
| 加密对象 | API Key、豆包配置等敏感字段 |

### 16.3 安全建议（认真读）

1. **不要暴露公网**：没有登录系统，谁访问谁就能用你的 Key。
2. **局域网也要小心**：同一 Wi-Fi 下的人可直接访问。
3. **`data/` 是明文 + 加密混合**：会话内容是明文，别把敏感对话留在里面。
4. **备份文件等同密钥**：拿到 tar.gz 等于拿到你全部数据。
5. **定期轮换 API Key**：尤其在借给别人用过之后。

## 十九、故障排查手册

### 19.1 启动类

| 现象 | 原因 | 处理 |
|---|---|---|
| `dart: command not found` | 未装 Dart | `pkg install dart` |
| `Error: Couldn't resolve the package 'ddsh'` | 没跑 `pub get` | `dart pub get` |
| `Address already in use` | 端口被占 | `pkill -f 'app'` 或 `DSH_PORT=8081 ./app` |
| 编译 OOM | 内存不足 | 改用 `dart run bin/main.dart` |
| `app` 不存在 | 没编译 | `python3 st.py --rebuild` |

### 19.2 访问类

| 现象 | 原因 | 处理 |
|---|---|---|
| 浏览器拒绝连接 | 进程没起 / 端口错 | `st.py --status`，确认端口 |
| 局域网访问不了 | 手机防火墙 / 不同网段 | 确认同 Wi-Fi；用 IP 不是 `127.0.0.1` |
| 页面白屏 | JS 缓存旧版 | 强刷；检查 `?v=` 版本号 |
| 界面语言错乱 | 词典未加载 | 控制台看 `locales/*.js` 是否 404 |

### 19.3 请求类

| 错误 | 含义 | 处理 |
|---|---|---|
| 401 / 403 | Key 无效或无权限 | 重填 Key；确认模型已开通 |
| 429 | 频率/额度限制 | 等一会，或换模型 |
| 400 `InvalidParameter` | 参数不被该模型接受 | 系统会自动摘掉出问题参数重试一次 |
| `TosResourceNotFound` 404 | TOS 桶里没这个对象 | 改用本地直传（默认即是） |
| 流式中断 | 网络抖动 / 系统杀后台 | `termux-wake-lock`，关电池优化 |
| 返回空内容 | 上游限流或超时 | 重试；看后端日志 |

### 19.4 数据类

| 现象 | 原因 | 处理 |
|---|---|---|
| 会话不见了 | 删了 `.sts` / 还原覆盖 | 从备份恢复 |
| Key 每重启就失效 | `ds_master.key` 丢了 | 固定 `DS_MASTER_KEY`，并纳入备份 |
| 文件上传卡住 | 分片目录残留 | 清 `data/ds_files/chunks/<uploadId>/` |
| 备份还原后空白 | 没重启后端 | 重启进程 |

### 19.5 语言类

| 现象 | 处理 |
|---|---|
| 中文界面出现日语 | 该源串在 `zh.js` 缺条目，按 7.4 自检补齐 |
| 某文案直接消失 | 译文为空串，补上文本 |
| 切语言没反应 | `i18n.js` 未加载或 `html[lang]` 非法 |
| 数值单位不对 | 检查占位符 `{0}` 是否在译文中保留 |

### 19.6 看日志的正确姿势

```bash
python3 st.py --logs 200          # 最近 200 行
./app 2>&1 | tee /tmp/ddsh.log    # 前台跑并落日志
```

日志里出现 `⚠️ ポート ... が使用できません` 表示端口被占，会自动重试；出现 500 多半是上游返回异常，往上翻能看到具体 URL 与响应体。

## 二十、常见问答 FAQ（100 问）

### A. 安装与部署（Q1–Q15）

**Q1. 需要 root 吗？**
不需要。全部功能在普通用户下可跑；设备操控走 adb `uid=2000`，也不需要 root。

**Q2. 需要装 Shizuku 吗？**
不需要。本项目用 adb 通道（`adb_up.sh`）实现等效权限，不依赖 Shizuku。

**Q3. 一定要用 Termux 吗？**
不一定。任何能跑 Dart 3 的环境都行（Linux、macOS、VPS）。Termux 只是最常见的手机方案。

**Q4. 支持 Windows 吗？**
Dart 本身跨平台，但 `st.py`、`adb_up.sh`、`auto.py` 是 shell/Python 脚本，Windows 下需要 WSL 或手动改路径。

**Q5. 最低 Android 版本？**
Android 7.0。低于此版本 Termux 与 adb 无线调试支持都不完整。

**Q6. 要装数据库吗？**
不用。数据是文本文件 + 目录结构，没有 SQL、没有 Redis。

**Q7. 为什么 `dart pub get` 什么都没下载？**
因为本项目 `dependencies: {}`，零第三方依赖，这是设计目标而不是故障。

**Q8. 编译产物多大？**
约 9–10 MB，单文件可执行。

**Q9. 编译要多久？**
中端手机上通常 1–3 分钟；内存紧张时会慢，可以先用 `dart run` 顶着。

**Q10. 可以放 U 盘 / SD 卡跑吗？**
可以，但 SD 卡读写慢会让文件管理与备份明显变卡，建议放内部存储。

**Q11. 需要多大存储？**
代码约 30 MB，Dart SDK 约 300 MB，数据看你存多少文件，建议留 500 MB 以上。

**Q12. 能多设备同时访问吗？**
能，局域网内多台设备可同时打开；但**没有账号体系**，所有人共享同一份数据和 Key。

**Q13. 怎么更新到新版本？**
`git pull` 后重新 `dart compile exe bin/main.dart -o app`，再 `st.py --restart`。`data/` 不受影响。

**Q14. 更新会不会覆盖我的数据？**
不会。`data/` 在 `.gitignore` 里，`git pull` 不碰它。

**Q15. 可以用 Docker 吗？**
可以自己写 Dockerfile 跑 Dart，但设备操控类功能在容器里用不了（拿不到 adb）。

### B. 启动与运行（Q16–Q28）

**Q16. 端口怎么改？**
`DSH_PORT=8080 ./app`。或在启动脚本里导出环境变量。

**Q17. 为什么关掉 Termux 窗口服务就没了？**
前台进程随终端退出。用 `python3 st.py --daemon`（`setsid` 脱离终端）或 `--install-service`。

**Q18. 怎么让它开机自启？**
装 `Termux:Boot`，把启动命令写进 `~/.termux/boot/` 下的脚本；或 `python3 st.py --install-service`。

**Q19. 后台跑着跑着就断了？**
安卓省电策略杀进程。执行 `termux-wake-lock`，并在系统设置里给 Termux 关电池优化、允许自启动、后台设为无限制。

**Q20. 怎么看服务有没有活着？**
`python3 st.py --status`，或 `curl -s 127.0.0.1:9999/api/displaymodels`。

**Q21. 日志在哪？**
`python3 st.py --logs` 直接看；前台运行时可 `tee` 到文件。

**Q22. 启动报「端口被占用」怎么办？**
先 `pkill -f app`，或换端口。日志里会显示自动重试。

**Q23. 支持 HTTPS 吗？**
本身只监听 HTTP。要 HTTPS 请在前面套 Nginx/Caddy 反向代理。

**Q24. 能不能远程访问？**
技术上可以（端口转发/内网穿透），但**强烈不建议**：没有登录验证，暴露即等于把 Key 交给全网。

**Q25. 重启后数据还在吗？**
在。数据都在 `data/`，与进程生命周期无关。

**Q26. 可以同时跑两个实例吗？**
可以，但必须用不同 `DSH_PORT` 和不同工作目录，否则会抢同一份 `data/`。

**Q27. `st.py --no-aot` 是什么？**
跳过 AOT 编译，直接 `dart run`，省编译时间，启动略慢。

**Q28. 服务起来但界面空白？**
先看浏览器控制台是否有 404；常见是 `locales/*.js` 或 `deepseek-chat.js` 的 `?v=` 缓存没更新，强刷一次。

### C. 语言与显示（Q29–Q38）

**Q29. 支持哪六种语言？**
日语、简体中文、英语、韩语、俄语、法语。

**Q30. 默认语言是什么？**
`ja`（日语），它是词典的源语言，其他语言缺项时回退到它。

**Q31. 为什么默认是日语不是中文？**
因为源串就是日语，`DEFAULT_LANG = 'ja'`。想默认中文，改 `i18n/i18n.js` 的 `DEFAULT_LANG`。

**Q32. 中文界面为什么不能出现日语？**
这是本项目的硬性质量要求：任意语言界面只能出现该语言（含必要的专有名词原文），跨语言残留视为 bug。

**Q33. 英文界面出现「豆包」算 bug 吗？**
算。品牌名应转写为 `Doubao`；`墨迹` → `Moji`；`Server酱` → `ServerChan`。

**Q34. AI 的回答会被翻译吗？**
不会。用户生成内容与 AI 正文属于跳过区，永远原样显示。

**Q35. 代码块会被翻译吗？**
不会。`pre`、代码块、`console.log` 一律跳过。

**Q36. 加一条新文案要改几个文件？**
6 个语言词典各一条，共 6 处；源串必须是日语。

**Q37. 怎么快速查某条文案缺哪个语言？**
用 7.4 的三条命令：数条目、搜跨语言字符、搜空译文。

**Q38. 切换语言要刷新吗？**
不用，热切换会重扫 DOM。若个别元素没变，强刷一次即可。

### D. 对话与模型（Q39–Q52）

**Q39. 默认模型是哪个？**
`deepseek-flash`。

**Q40. `deepseek-chat` 和 `deepseek-reasoner` 还能用吗？**
能，属于旧名，服务端会路由到 flash。

**Q41. 能加自己的模型吗？**
能，设置里「追加」输入模型名即可，只要上游接受。

**Q42. 模型路由是干什么的？**
把不同任务（闲聊、代码、工具调用、翻译）分流到不同模型，兼顾成本与效果。

**Q43. 深度思考有什么用？**
让模型先推理再作答，复杂题正确率更高，代价是更慢、更贵。

**Q44. 思考内容能关掉吗？**
能，它默认折叠，不看就等于关；也可以关掉对应的思考开关。

**Q45. 会话存在哪？**
`data/deepseek_chat/sessions/*.sts`，一个会话一个文件。

**Q46. 会话有上限吗？**
没有硬限制，取决于存储。单会话太长会拖慢加载，建议长对话适时新开。

**Q47. `@` 提及怎么用？**
输入框打 `@` 选择另一个会话，它的内容会作为参考上下文并入本次请求。

**Q48. 能导出对话吗？**
用备份功能导出 tar.gz，里面就是 `.sts`；也可以直接拷文件。

**Q49. 消息能编辑重发吗？**
界面支持重试与继续；编辑后重发需重新发送（历史保留）。

**Q50. 流式中断会丢内容吗？**
不会。中断会把已生成部分保存下来。

**Q51. 为什么回复有时很慢？**
上游排队、思考链长、联网搜索都耗时。可在峰谷低谷时段跑重活。

**Q52. 能开多个并发生成吗？**
同一会话不建议并发，容易上下文错乱；不同会话可并行。

### E. 计费与 token（Q53–Q64）

**Q53. 计费数据从哪来？**
上游返回的 usage 字段（请求里带 `stream_options.include_usage`）。

**Q54. 为什么以前没有 token 显示？**
早期请求没开用量返回，现在已开；且对不支持该参数的模型会自动摘掉后重试。

**Q55. 豆包 2.1-lite 单价多少？**
输入 0.8、命中 0.16、输出 2.7、音频输入 12（音频命中 2.4），单位元/百万 tokens。

**Q56. 有峰谷价吗？**
豆包 2.1-lite 无峰谷倍率，任何时段同价。

**Q57. 缓存命中为什么便宜这么多？**
命中价是输入价的 20%，命中越多越省。

**Q58. 音频 token 会被重复计费吗？**
不会。音频 token 先按音频单价算，再从文本输入里扣除，不重复。

**Q59. 金额是四舍五入吗？**
按原始 token 精确计算，展示保留 4 位小数。

**Q60. 刷新页面金额会消失吗？**
不会。usage 随消息写入 `.sts`，刷新、重启、换模型都在。

**Q61. 为什么我改了单价，历史金额也变了？**
因为永久保存的是 token 计量，金额是按当前价目实时算的。这是正确行为。

**Q62. 为什么有些模型不显示金额？**
价目表里没有的模型（如豆包 pro/turbo）只显示 token，不编造价格。

**Q63. token 数和我自己算的对不上？**
注意区分「输入总数 / 命中 / 未命中 / 输出 / 音频」五个口径，容易漏掉命中部分。

**Q64. 费用能在本地汇总吗？**
可以写脚本扫 `sessions/*.sts` 里的 usage 字段累加，格式是管道分隔，很好解析。

### F. 豆包与多模态（Q65–Q76）

**Q65. 豆包和 DeepSeek 要都配吗？**
只配 DeepSeek 就能用；想用图像/视频/语音再配豆包。

**Q66. `TosResourceNotFound` 是什么？**
方舟按 `tos://` 去桶里读对象，桶里没有这个文件。通常是桶名用了官方示例桶。

**Q67. 怎么修 TOS 404？**
默认 `useFilesApi=false`，走本地直传（`/files`）。要用 TOS 引用，需设 `useFilesApi=true`、填 `tosBucket`，并把文件放进**自己账号**的桶且授权方舟读取。

**Q68. 视频「预处理 0 秒」是真 0 秒吗？**
不是，是显示 bug。后端此前不发 `waited` 字段，前端回落到 0；现已按 tick 回传真实秒数。

**Q69. 视频大小有限制吗？**
本地直传受方舟接口限制；超出阈值会自动压缩。文件管理侧单文件上限 5 GB。

**Q70. 视频会分片上传吗？**
视频链路的直传是整段 multipart，不分片；文件管理才是 64 MB 分片。

**Q71. 图像生成用哪个模型？**
`doubao-seedream-5-0` / `5-0-pro`，图生图用 `doubao-seededit-3-0-i2i`。

**Q72. 实时语音要什么配置？**
需要方舟 RTC 相关凭据；配好后从语音入口进入。

**Q73. TTS 用的是哪家？**
豆包 TTS 与 Edge TTS 两条通道，按配置选择。

**Q74. 语音识别支持中文吗？**
支持，走 `/api/doubao/asr`。

**Q75. 豆包模式为什么建议单开会话？**
工具链长，容易把上下文撑爆导致会话中断；单独开会话更稳。

**Q76. 抖音百科插件要额外配置吗？**
走豆包检索链路，配好豆包 Key 即可。

### G. 文件、备份与数据（Q77–Q88）

**Q77. 单文件最大多少？**
5 GB。

**Q78. 分片多大？**
64 MB 一片，合并时 1 MB 流式拷贝，防内存爆。

**Q79. 上传中断要重传全部吗？**
不用。分片留在 `chunks/<uploadId>/`，重传会覆盖同序号分片。

**Q80. 备份包含哪些内容？**
整个 `data/`：会话、配置、论坛、单词本、角色卡、公告、文件数据。

**Q81. 备份不含什么？**
`app` 二进制、源码、`.dart_tool/`。

**Q82. 还原后 Key 用不了？**
因为没带 `ds_master.key`。固定 `DS_MASTER_KEY` 或把 key 文件纳入备份。

**Q83. 还原是覆盖还是合并？**
覆盖。还原前先备份当前数据。

**Q84. 能手动改 `.sts` 吗？**
可以，但要遵守转义规则（换行 `\n`、竖线 `\p`、反斜杠 `\\`），改坏了行会解析失败。

**Q85. 数据能迁移到新手机吗？**
能。整个 `ddsh/` 目录拷过去（含 `data/`），或备份包还原。

**Q86. `.sts` 为什么不存 JSON？**
单行存储、易追加、易 grep、坏一行不毁全文件。

**Q87. 文件存哪？**
`data/ds_files/blob/`，元数据在 `meta/`。

**Q88. 数据会传云端吗？**
不会。除了你主动调用的 API 请求，数据全部留在本地。

### H. ADB 与设备操控（Q89–Q96）

**Q89. adb 需要 root 吗？**
不需要。`uid=2000` 就是 shell 用户，接近 Shizuku 权限。

**Q90. `adb_up.sh` 干了什么？**
起脱离终端的 adb server、连接 `127.0.0.1:5555`、校验 `uid=2000`。

**Q91. 一直连不上怎么办？**
确认无线调试已开、已配对；然后重跑脚本。仍失败就重启 adb server。

**Q92. 输中文为什么不能直接 `input text`？**
`input text` 遇到中文会乱码，必须切 ADB Keyboard 并用 Base64 广播。

**Q93. 输完必须切回搜狗吗？**
必须。用户手机环境用前什么样，用完就得什么样。

**Q94. 没装搜狗怎么办？**
先装搜狗；或改脚本里的 IME 常量为用户实际使用的输入法。

**Q95. 会不会误点广告弹窗？**
`auto.py` 会识别并关闭弹窗，但点击前必须确认目标是弹窗而非功能按钮。

**Q96. 能自动装/卸载应用吗？**
能，`auto.py` 支持启动、停止、卸载；安装需提供 APK 路径。
